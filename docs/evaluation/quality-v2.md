# Quality evaluator v2: explicit ranked-input contract

Status: additive offline evaluation contract; evaluator semantics version **2.0.0**,
input/report schema **2**. This is not model-quality evidence or a production search
runner. It neither modifies nor implicitly migrates the [frozen public v1 bundle](public-corpus-contract-v1.md).
The v1 `quality.py`, `metrics.py`, `reporting.py`, fixture validator and
`scripts/media_quality_eval.py` retain their independent contracts/history.

## Entry points and closed documents

- `mdrack.eval.quality_v2.validate_quality_input(document: object) -> dict[str, Any]`
- `mdrack.eval.quality_v2.evaluate_quality_v2(document: object) -> dict[str, Any]`
- `mdrack.eval.quality_io.loads_quality_input(text: str) -> dict[str, Any]`
- `mdrack.eval.quality_io.validate_quality_report(document: object) -> dict[str, Any]`
- `mdrack.eval.quality_io.dumps_quality_report(report: object) -> str`
- `mdrack.eval.quality_io.loads_quality_report(text: str) -> dict[str, Any]`

Invalid inputs raise the existing privacy-safe `QualityEvaluationError`; diagnostics
never echo offending identities, keys, paths or raw JSON exceptions. JSON readers
reject duplicate keys, NaN/Infinity, unsupported versions, missing/unknown fields,
booleans in numeric fields and malformed types. Integer inputs are in
`[0, 2^53 - 1]`; cutoffs are positive. Validators return independent copies and do
not mutate caller input. Machine-readable structural companions:

- [quality-input-v2.schema.json](../../tests/evaluation/schemas/quality-input-v2.schema.json)
- [quality-report-v2.schema.json](../../tests/evaluation/schemas/quality-report-v2.schema.json)

The Python validators are authoritative for cross-field, matching, scope,
coverage, nullability and aggregation constraints; structural JSON Schema alone
cannot establish those invariants or completeness of the caller's corpus.

Input top-level fields (all required): `contract="mdrack.quality-input"`,
`schema_version=2`, SHA-256 `corpus_ref`, `judgments_ref`, `implementation_ref`, and
nonempty `cases`. References must identify the caller's actual versioned artifacts;
placeholder digests in the manual examples are **synthetic**, not corpus claims.
The report adds `input_ref`, a digest of the complete canonical input including
ranked order, scopes, judgments and policy. Changing judgments or policy changes
that identity; model/profile comparisons require the same declared scope/gold.

Each case has exactly: `case_id`, `case_type` (`positive`/`negative`), `target`
(`resource`/`unit`), `match` (`identity`/`temporal`), increasing unique `cutoffs`,
`scope`, `judgment_policy` (`complete`/`pooled`), `unjudged_policy`,
`temporal_policy`, `judgments`, `ranked`. There is no query text or source content.
The already-ranked list is supplied by the caller, never generated by a model or
an overlap ranker inside this evaluator.

A scope is a nonempty list of unique `{resource_id, source_revision}` pairs.
Resource target permits **one selected revision per resource**. Unit target may
explicitly admit several revisions; they never match across revisions. Scoped
identity judgments must have unique unit IDs across those revisions/owners,
so one logical unit ID cannot inflate the unit-gold denominator. All ranked
results must belong to scope. Gold outside scope is excluded from the denominator
and counted as `excluded_judgments`; its shape/duplicate identities are still
validated. Positive cases require scoped positive gold. A scoped zero-gold case
must be **explicitly declared negative**, not silently assigned zero positive metrics.

Each ranked record contains `resource_id`, `source_revision`, `unit_id`,
`intervals`, `timestamp_ms`; a judgment has those fields plus unique
`judgment_id` and integer `grade` in 0..3. Empty intervals are `[]`; absent
unit/timestamp is `null`. Grade 0 and unjudged are distinct; only grade > 0 gives
hit or gain. Duplicate judgment matching targets, even with different IDs or
grades, fail. Ranked duplicates are rejected over the **whole** list before
metrics, including positions beyond the largest cutoff:

- resource target: repeated resource ID, even through different units/revisions;
- unit target: repeated unit ID.

There is no silent deduplication/reranking or repair of a malformed public answer.
K counts distinct admitted resources or units respectively. Identity matching
requires equal resource/revision, plus unit ID for unit target. Resource judgments
have null unit ID; ranked resource entries may carry unit provenance, ignored for
matching. Identity entries contain no temporal coordinates.

## Temporal policy and deterministic one-to-one matching

Temporal matching is a unit-target mode independent of old recipe unit IDs.
Temporal gold has null `unit_id`; ranked units require an ID. Each entry has
exactly one coordinate kind: nonempty `intervals` or integer `timestamp_ms`.
`temporal_policy` is mandatory:

```json
{"interval_iou": 0.5, "timestamp_tolerance_ms": 10}
```

Thresholds are caller-declared, not hidden defaults: finite `0 < interval_iou <= 1`
and nonnegative integer tolerance. Timestamp distance is inclusive (`<=`).
Intervals are sorted, separated, nonempty, half-open `[start, end)` ranges.
Overlapping, touching, reversed and unsorted component intervals are rejected;
author a merged component when adjacent intervals are intended as one range.
Compound IoU is intersection length over **union length**, never convex-hull IoU.
A hull covering two small separated gold intervals can therefore fail the policy.
No interval/timestamp cross-kind matching is attempted.

Matching processes ranked positions in order. Eligible gold must have equal
resource **and source revision**, the same coordinate kind, and satisfy the
policy. Among **unconsumed positive** gold, choose highest interval IoU or smallest
timestamp distance; ties use lexical `judgment_id`, not input order or grade.
Consume both endpoints once. A lower-ranked overlapping unit cannot earn a
second hit/gain against the same gold. This is deterministic rank-greedy matching,
not global maximum-cardinality/weight matching; changing that rule requires a new
semantics version. Input IDs are opaque ordinal tie-break identities and must
stay fixed across compared profiles.

Coverage is computed independently of consumption: a second unit overlapping
already-consumed positive gold is still judged but earns no second gain. An
eligible positive labels a result judged-positive; otherwise eligible grade-0
gold labels it judged-zero; otherwise it is unjudged. With overlapping positive
and zero regions, positive eligibility takes precedence (not judgment order).

For matched intervals, boundary errors are absolute errors of the outer first
start and last end, **not component-alignment errors**; IoU measures gaps.
Temporal summaries include `gold`, `matches`, `hit`, `recall`, `interval_matches`,
`timestamp_matches`, `mean_iou`, `mean_start_error_ms`, `mean_end_error_ms`, and
`mean_timestamp_error_ms`. Means use only actual positive pairs of that kind.
No matching samples means **null**, not perfect zero; miss counts/recall remain
observable. Identity rows have `temporal=null`.

## Coverage, metrics and negative queries

`complete` requires `unjudged_policy="error"` and coverage of **every returned
result**, not merely top-K. The caller asserts exhaustive gold in the declared
scope; the evaluator cannot prove judgments for an unseen corpus from ranked
results alone. `pooled` requires `unjudged_policy="nonrelevant"`, labels
`recall_basis="judged_pool"`, and treats unjudged as no gain without relabeling it
as explicit grade 0. Reports show `judged_returned`, `unjudged_returned`,
`zero_grade_returned`, and `judged_fraction` at each K. Empty-return coverage is
null (no denominator). Full-gold input reports `recall_basis="complete_gold"`.

Each cutoff row reports `k`, `returned`, coverage, `relevant_hits`, `recall`,
`mrr`, `ndcg`, `hit`, `negative_returned`, `empty`, `temporal`.
Positive metrics use matched positives; Recall divides by all scoped positive
gold. MRR uses the first relevant position within K. nDCG uses `2^grade - 1`
discounted by `log2(position + 1)`, normalized by sorted scoped positive grades.
Unmatched/unjudged/zero/consumed-repeat positions keep their position and zero gain.
No precision metric/denominator is introduced or changed.

Negative cases have no scoped positive gold; all positive relevance metrics are
null, not misleading zeroes in positive averages. `negative_returned` counts
returned items at K, and `empty` is 0/1. These measure behavior at the caller's
chosen refusal policy; this evaluator adds no search threshold or refusal model.
For positive cases both negative-only metrics are null.

Results use case ordinals, not caller IDs. Aggregation is separate by case type,
target, match mode, judgment policy, cutoff **and temporal-policy digest**. Every
metric mean has an explicit non-null case `samples` count. Temporal error summary
means are means of case-level matched-pair means, not match-count-weighted pooled
means. No samples means null. Inapplicable positive/negative metrics never enter
the other's denominator. No constant duplicate-rate measurement is fabricated:
duplicates are an input invariant violation.

The report (`contract="mdrack.quality-report"`, schema 2) includes the references,
`evaluator_version`, `cases`, ordinal `results`, grouped `summary`,
`evaluation_elapsed_ms`, `evidence_boundary="offline/already-ranked"`, and
`search_latency_measured=false`. Evaluation elapsed time is **not search latency**.
All report strings are fixed enums or SHA-256 references. Report readers enforce
closed fields, types, coverage/null relationships and summaries recomputed from
results; they cannot prove an arbitrary supplied result originated from a model.

## Actual consumer and manual oracle

From a qualified source environment:

```bash
uv run --no-sync --offline python scripts/quality_eval_v2.py --input tests/evaluation/manual-v2/input.json --output /owned/report.json
uv run --no-sync --offline python scripts/quality_eval_v2.py --report /owned/report.json
uv run --no-sync --offline pytest tests/unit/test_eval_quality_v2.py tests/unit/test_eval_quality_io.py
```

`--input` runs the validator and real evaluator, then the report validator and
serializer. `--report` validates/reads v2 output without evaluating again. Input
is bounded to 8 MiB; output is stdout or an explicitly selected atomic file.
Failed validation preserves existing output and emits only a fixed JSON error,
without paths or traceback. Input/report options are mutually exclusive. v1
input/report is refused, never reinterpreted; legacy tooling still uses v1.

[Manual v2 input](../../tests/evaluation/manual-v2/input.json) and
[hand-calculated expectations](../../tests/evaluation/manual-v2/expected.json)
cover resource zero-before-positive, one-of-two positives, temporal one-to-one,
foreign owner, wrong revision, compound gaps, timestamp tolerance, negative empty
and nonempty, and scope-correct gold. The
[duplicate-resource example](../../tests/evaluation/manual-v2/invalid-resource-duplicate.json)
is an intentional contract failure. These fixtures are public synthetic identities
and coordinates, with no media, source content, private data or provider responses.
The adjacent unit tests add malformed-input, tie/rank-order, missing-match,
coverage, serialization, privacy, CLI write/refusal and v1 preservation oracles.

## Integration/version boundary

This adds a separate app evaluation module, JSON input/report schema 2, semantics
version 2.0.0, CLI script and manual fixture. It does **not** change app/core/sqlite
public search/engine/CLI wire exports, dependencies, migration identity,
requires-python, package pins or frozen v1 history. Therefore no core RC export
snapshot or dependency-lock update is intrinsically required by these additive
names. Package release version/pin/lock/tooling synchronization belongs to the
already-authorized V owner when this delta is integrated into the agreed current
candidate; it is not forbidden or silently waived. Do not stamp an unintegrated
snapshot as the current app release, or use the old installed wheel to qualify it.

W5 still owns real versioned media corpora, complete annotations/dev/held-out and
negative-query policy, RU/EN/cross-language, production public search execution,
paired profile comparisons and declared thresholds. This manual offline contract
work proves none of model/native-media usefulness, latency/cost, installed release
readiness or changing checkout integration.
