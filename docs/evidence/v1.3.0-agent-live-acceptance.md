## Search, filters, reads, and durability

The first acceptance harness made 26 installed-CLI calls. Text search across all
successful families returned `document`, `raw_text`, `image`, and `video` resources.
Scoped text search returned one result in each of `notes`, `images`, `video`, and
`frames`; `audio` returned zero because the real WAVE processor did not produce a
persisted audio resource. The video search payload contained two timestamp-bearing
fields.

`--mode semantic --provider fake` and `--mode hybrid --provider fake` both completed.
They are command-surface and local persistence evidence only: the deterministic fake
provider is not semantic-quality or live-LM-Studio evidence. The typed
`resources search` filter for image kind and PNG media type returned two results, and
both `resource inspect` and `metadata show` returned their documented public projections.

The two original installed public gaps are closed on the exact post-repair wheel:

1. A real-video continuation checked the raw `--kind video` form in text, semantic
   (`--provider fake`), and hybrid (`--provider fake`) modes. All three returned the
   payload-free `VALIDATION_ERROR` envelope instead of successful `INTERNAL_ERROR`.
   The invalid unified `--scope frames --kind video` combination also returned
   `VALIDATION_ERROR`. The documented permitted path,
   `--preset balanced --target resource --kind video --media-type video/mp4`, returned
   a populated resource result from that same actual local video.
2. A scoped frame search exposed a public evidence unit; `mdrack read unit` returned
   its portable frame projection with `video_frame` timing. Applying `read chunk
   --context neighbors` to that non-text unit now returned `VALIDATION_ERROR`, rather
   than the prior `STORAGE_ERROR`. This is a fail-closed compatibility result; it does
   not reinterpret a frame as a Markdown text chunk.

After the post-repair video process had exited, separate fresh installed CLI processes
reopened the same root. `status`, scoped video search, and `read unit` all succeeded; the
reopened catalog still had exactly one catalog file and the repaired public video evidence.
