## Лицензия MDRack

MDRack распространяется по неизменённой стандартной лицензии MIT. Канонический текст
находится в [`../LICENSE`](../LICENSE); именно он имеет приоритет над этой страницей.

Для кода и сопроводительной документации MDRack это означает следующее:

- можно использовать MDRack в коммерческом продукте, изменять его, распространять,
  сублицензировать и продавать копии;
- во всех копиях или существенных частях должны сохраняться текст лицензии и точное
  уведомление `Copyright (c) 2026 VladimirMonin`;
- MDRack предоставляется «как есть»: MIT не даёт гарантий пригодности, отсутствия
  нарушений прав третьих лиц или ответственности авторов за ущерб.

Эти правила относятся к собственному коду, документации и проектному skill MDRack, а
также к четырём базовым Python-дистрибутивам:

1. `mdrack` 1.3.0;
2. `mdrack-core` 1.0.0rc1;
3. `mdrack-media` 1.0.0rc1;
4. `mdrack-sqlite` 1.0.0rc2.

Каждый из восьми ожидаемых архивов (wheel и sdist для каждой позиции) должен содержать
полный канонический `LICENSE` и объявлять MIT в пакетных метаданных. Это требование
контракта выпуска; его соблюдение доказывается только проверкой точных собранных
архивов, а не этой страницей.

## Зависимости, которые устанавливает resolver

Базовые wheel/sdist не включают сторонние Python-библиотеки просто потому, что они
указаны в `Requires-Dist`: их отдельно устанавливает resolver. Их лицензии остаются
лицензиями соответствующих правообладателей и не становятся MIT-лицензией MDRack.

Полный зафиксированный перечень обязательного графа для Linux и Windows, включая
Windows-only `colorama`, находится в
[`../THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md). Для каждой библиотеки там
указаны точная версия, проверенный источник текста лицензии, коммерческое разрешение,
отсутствие лицензионной роялти, статус `resolver-only` и обязанности при будущей
самодостаточной поставке. Отдельно объяснены `certifi` под MPL-2.0 и
`typing-extensions` под PSF-2.0.

## Внешние программы вне поставки

Выбранные вызывающей стороной внешние программы и модельные артефакты не входят в
MDRack или четыре базовых Python-дистрибутива. Они требуют отдельной проверки только
если когда-нибудь будут встроены в поставку, перепубликованы или проданы вместе с ней.

## Отдельная граница для Windows EXE

Самодостаточный Windows onedir EXE не входит в проверяемый набор из четырёх Python
дистрибутивов. До его коммерческой поставки нужен отдельный Windows-сборочный манифест:
он должен перечислять все встроенные файлы и их лицензии, а пакет должен включать
применимые тексты лицензий/уведомлений вместе с MDRack `LICENSE`. Пока такого манифеста
и проверки нет, Python wheel/sdist нельзя использовать как доказательство готовности EXE.
См. [сборку Windows EXE](windows-exe-build.md).
